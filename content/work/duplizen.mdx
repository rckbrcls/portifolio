## Problem

A hidden-role party game needs to keep room membership, private roles, and game
state coordinated while staying simple enough for players to join from their
own devices.

## Solution

Duplizen combines room creation, role assignment, real-time state updates, and
multilingual presentation in a responsive progressive web application.

## My contribution

I designed and implemented the product, application flows, multiplayer data
model, database policies, and controlled game-state transitions.

## Architecture

- Next.js, React, and TypeScript provide the browser application.
- Supabase and PostgreSQL persist rooms, players, roles, and game state.
- Row-level security narrows which records a participant can access.
- RPC functions coordinate shared transitions near the database.
- Realtime subscriptions propagate relevant state changes to connected
  players.
- PWA support keeps the experience installable without requiring a native app.

## Technical choices

- Keep shared-state transitions close to the database instead of trusting every
  client to mutate the game independently.
- Use database functions and access policies to centralize multiplayer rules.
- Make joining a room work directly in a browser.
- Treat English, Portuguese, and Spanish as product behavior rather than a
  later translation layer.

## Trade-offs and limits

Realtime coordination improves group play but creates stronger consistency and
reconnection requirements than a single-device game. The public story does not
claim adversarial security, competitive fairness, or fault tolerance beyond
the implemented policies and transitions.

## Current status

Duplizen is active. I do not publish player counts, production scale, room
data, private role information, or security guarantees.
